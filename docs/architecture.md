# Architecture and canonical state

The application separates a Next.js/React presentation service from a FastAPI domain API. Next.js proxies versioned API and static asset routes to FastAPI. FastAPI/Pydantic own schemas, revisions, deterministic engineering calculations, and verification summaries. CadQuery/Open CASCADE generate the assembly solids and CAD exports. `public/app.js` loads current-revision component STL tessellations in Three.js; it does not create CAD or own engineering calculations. `data/project.json` is the local source of truth; an accepted edit retains the old state in history and writes a new monotonically increasing revision. The full candidate is Pydantic-validated before an atomic same-directory temporary-file replace. Failed writes leave the previous state file intact. Persistence remains single-process/single-writer: no interprocess lock, compare-and-swap, or multi-writer guarantee is implemented.

The current project is intentionally one constrained `spur_gear_pair` family. Its graph is implicit in the fixed two-component relationship: input gear teeth and module determine pitch diameter, tooth counts determine ratio, and ratio plus input speed/torque determine ideal output speed/torque. `GET /api/v1/project` returns revision, requirements, components, status, derived results, and validation. Exports are created on demand and carry the current revision in the filename/header.

CAD and report outputs are generated from one loaded `Design` snapshot per request. Each output is atomically written under a filename containing its revision and generator/report version, then recorded with a checksum in `artifacts/artifact-index.json`. `GET /api/v1/artifacts` lists metadata and marks records stale when their revision differs from the current project. `GET /api/v1/artifacts/{filename}` allows retrieval of retained prior outputs, verifies the checksum, and reports stale state in a response header. Current export routes always generate from the current snapshot. Historical outputs are retained as local files; there is no background job or object store.

This remains a constrained local architecture. PostgreSQL, authentication, explicit graph dependency edges, artifact lifecycle controls, and multi-process write coordination are future work. Keep model-provider adapters separate from deterministic calculations. The requirement provider protocol accepts only validated typed proposals and never executes model-generated code.
