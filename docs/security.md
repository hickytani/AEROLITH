# Security notes

This local demonstrator binds to loopback by default and has no accounts or secrets. It is not suitable for public deployment. There is no authentication, authorization, CSRF protection, rate limiting, multi-tenant boundary, audit service, or hardened storage. Project writes validate the full candidate and use a same-directory temporary file with `os.replace`; this protects against partial file replacement but does not provide multi-process locking or transactional coordination. A malformed existing project is surfaced as an API error and is not silently replaced. Artifact outputs and their index are also atomically replaced locally and checksummed, but updates to an artifact file and index are not one cross-file transaction. The patch endpoint accepts only fixed finite numeric fields and contains no arbitrary code execution or model-generated command path. An optional Ollama adapter is restricted to loopback and may produce only validated uncommitted proposals or component answers; it cannot modify project state or execute tools.

Training capture is disabled by default and requires both an explicit configuration toggle and per-request opt-in. Captured content is redacted for common token/credential patterns and emails, stored outside Git, and begins unreviewed; human review is a local single-user workflow rather than identity proof. Model, adapter, and cache files are excluded from Git. Before deployment, add per-user authorization, secure session handling, request limits, safe artifact storage, structured operational logging, security review, and isolation/resource controls for model/CAD workers. Never store provider secrets in the browser.
