# Security notes

This local demonstrator binds to loopback by default and has no accounts or secrets. It is not suitable for public deployment. There is no authentication, authorization, CSRF protection, rate limiting, multi-tenant boundary, audit service, or hardened storage. Project writes validate the full candidate and use a same-directory temporary file with `os.replace`; this protects against partial file replacement but does not provide multi-process locking or transactional coordination. A malformed existing project is surfaced as an API error and is not silently replaced. Artifact outputs and their index are also atomically replaced locally and checksummed, but updates to an artifact file and index are not one cross-file transaction. The patch endpoint accepts only fixed finite numeric fields and contains no arbitrary code execution or model-generated command path. Requirement text is processed by bounded local patterns; the optional provider boundary is not connected to a remote model.

Before deployment, use a supported production framework, strict request schemas, per-user authorization, secure session handling, request limits, safe artifact storage, structured operational logging, dependency pinning, security review, and isolation/resource controls for CAD or solver workers. Never store provider secrets in the browser. Do not add a provider until structured output validation and deterministic failure behavior are implemented.
